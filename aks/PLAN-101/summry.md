# 会话小结

## 主线目标

优化 `.agents/skills/bootstrap/SKILL.md`，让 Bootstrap Skill 能稳定支撑"递归拆解 Plan → 执行 → 回流修订"全闭环。题库系统是案例素材，不是改动目标。

## SKILL.md 关键演进（按时间顺序）

### 1. 引入 DONE 状态 + 执行回流机制
- 节点状态扩到 4 个：FRONTIER / READY / BLOCKED / DONE
- DONE 由外部执行系统标记；Bootstrap 不维护完整状态机
- 新增 `执行回流` 章节：处理执行端反馈
- 不引入 DIRTY 状态、不设状态机；状态流转由外部管理

### 2. READY 自检清单（4 项内部自检）
- 用户硬约束：Bootstrap 必须独立工作，不能依赖执行端反馈
- 自检 4 项：第一步可命名 / 完成标准独立可验 / 依赖闭合 / 单句目标
- 任一不通过 → 不标 READY，按对应失败动作处理
- 与回流分工：自检避免可避免的错，回流修补不可避免的错

### 3. 回流类型从 2 类扩到 3 类（最重要的修订）
- 原：A 设计错误 / B 新 blocker 风险
- 新增：**C 新需求 / 范围切片**
- A vs C 判定方法：原拆分**搞错了**（A） vs 原拆分**还不够细**（C）
- 一线反馈大多数是 C 类，SKILL 现在显式承认

### 4. 默认动作优先级表
按"改动最小、保留信息最多"排序：
1. **深拆现有节点**（C 默认）
2. 修 requirements
3. 新增兄弟节点
4. 重拆 / 删节点 / 改 P0（仅 A 类设计错误）

### 5. 业务范围切片的映射规则
- "一期 / V1 / MVP / 试点 / 灰度" 等业务术语 **永远不进 Plan 树**
- 它们是 Plan 树的**子集标记**，靠深拆 + status 优先级表达
- 反模式：把"一期"塞进 P0 的 name，缩窄整棵树

### 6. 失败模式补充
- C 类误判为 A 类
- 业务术语污染 Plan 树
- 回流处理不彻底
- 回流污染主线

## 我犯的关键错误（已写入 SKILL 失败模式）

处理用户的"一期 = 数学问答题 + 不批改 + 纯文本"反馈时：
- ❌ 重写 P0 + 删节点（P1.3 / P4 / P5.1 / P5.2）
- ✅ 应该：深拆相关节点（题型维度），把"一期"映射为 Plan 树子集

错误根因：把 C 类（粒度不够细）误判为 A 类（拆分错了），跳过优先级 1 直接做优先级 4。
