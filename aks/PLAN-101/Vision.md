# Vision

构建一个面向考生与管理员的在线题库与考试系统。

完整愿景包含五大能力：

- **题目库管理**：管理员对题目进行全生命周期管理（创建、编辑、删除、分类、检索、批量操作）
- **组卷能力**：管理员从题库选题组卷，配置考试参数（题目顺序、分值、考试时长等）
- **考试执行**：考生在线参加限时考试、顺序作答、提交答卷
- **批改能力**：对答卷进行评分（自动 / 半自动 / 人工）
- **成绩与统计**：考生查看个人成绩，管理员查看整体统计（参考人数、平均分、通过率等）

技术基础：复用既有项目中的 Next.js + tRPC + PostgreSQL + shadcn/ui 技术栈。

## Focus

- 纯数学问答题
- 题目来源于 CDN 的 yaml 文件，暂由外部过程管理
- 实现题目的展示
- 不需要回传答案，只要能显示下一步/下一题
- 全过程只读，不设计写数据库

- parent: P0
- children: P3.1, P3.2
- status: FRONTIER

  - **目标**：考生可参加限时考试、顺序答题、提交答卷
  - **完成标准**：

    - 考试过程中有倒计时显示
    - 考生可顺序答题并保存答案
    - 考生可提交答卷
    - 考试结束（时间到或提交）后自动收卷
  - **边界约束**：
    - 单人在线考试，不支持并发防作弊
    - 顺序答题，不支持跳题

    - 不支持暂停/继续
    - 答题输入仅纯文本
    - 提交后无分数反馈（一期不批改）
  - **关键假设**：
    - 考试过程不需要断点续传
    - 网络稳定，不需要离线支持
  - **风险点**：
    - 前端计时器的可靠性（浏览器刷新/关闭）
    - 答案保存的实时性要求

##### P3.1.2: 计时与超时处理
- parent: P3.1
- children: none
- status: BLOCKED
- blocker:
  - **架构决策待定**：计时机制是"客户端计时 + 服务器时间戳验证"还是"服务器主动触发"？
    - 选项A（推荐）：客户端倒计时，时间到提交时服务器验证时间戳（简单可行）
    - 选项B：服务器轮询或推送（实现复杂，一期不必要）
  - **影响**：影响 auto-submit 的实现方式和可靠性
- requirements:
  - **目标**：考试时间到时自动收卷
  - **完成标准**（选项A）：
    - 客户端根据开始时间 + 考试时长计算截止时间
    - 客户端倒计时显示
    - 时间到后考生无法继续答题
    - 提交时服务器验证时间戳，超时则强制收卷
    - 服务器记录最终状态为 submitted
  - **完成标准**（选项B，待选）：
    - 服务器维护计时任务
    - 时间到主动触发提交
    - 需要服务器推送机制（WebSocket/SSE/轮询）
  - **边界约束**：
    - 不支持延迟（时间到即收卷）
  - **关键假设**：
    - 时间戳验证在一期范围内可接受
