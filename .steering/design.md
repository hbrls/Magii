## 设计与架构

### 语言与工具

| 目的 | 工具 | 说明 |
|------|------|------|
| 配置格式 | Markdown | 主要配置文件格式 |
| 命令定义 | Markdown | 每个命令的 COMMAND.md |
| 模板 | Markdown | references/ 下的模板 |

### 框架与规范

| 用途 | 框架/规范 | 说明 |
|------|-----------|------|
| 工作流定义 | Markdown + 状态机 | Task 的 Do/Check/Act 结构 |
| 命令系统 | 文件系统 | 基于目录的命令定义 |
| 模板系统 | 参考模板 | references/ 目录 |

### 基础设施

| 组件 | 设计选择 | 说明 |
|------|----------|------|
| 版本控制 | Git | 项目使用 Git 管理 |
| 代码托管 | GitHub | 远程仓库 origin: git@github.com:hbrls/magii.git |
| IDE 集成 | 多工具支持 | Windsurf, Cursor, CLAUDE, Cline |

## 性能目标

由于 Magii 是元项目（定义规范而非实现功能），暂无传统意义上的性能指标。

## 可扩展性要求

- **支持多 IDE**: 可扩展支持新的 AI 工具
- **命令可扩展**: 通过添加新命令扩展功能
- **模板可扩展**: 参考模板可按需添加

## 安全要求

### 认证与授权

- 无后端服务，仅静态配置文件
- 依赖 GitHub 仓库的访问控制

### 数据保护

- 所有配置存储在本地仓库
- 无敏感数据存储

## 开发环境

### 必需工具

- Git (版本控制)
- Markdown 编辑器 (查看和编辑配置)
- CLI 工具 (执行命令)

### 初始化

1. 克隆仓库
2. 安装 Markdown 查看工具（可选）
3. 根据使用的 IDE，配置对应的规则加载

## 设计债务

### 已知问题

| 问题 | 影响 | 优先级 | 计划 |
|------|------|--------|------|
| 多 IDE 配置重复 | 维护成本高 | 中期 | 统一配置格式 |
| 模板分散 | 查找不便 | 低 | 建立索引 |

## 约束

### 必须使用

- **Markdown**: 所有配置文件使用 Markdown 格式
- **Git**: 版本控制使用 Git
- **Living Document 模式**: 公约文档末尾的 Changelog 遵循约定

### 必须不使用

- **二进制配置文件**: 不使用二进制格式
- **硬编码值**: 避免在代码中硬编码配置

### 推荐做法

- **模块化**: 命令和配置按功能模块化
- **模板化**: 重复性内容使用模板
